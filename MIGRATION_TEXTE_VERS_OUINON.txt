###########################################################
#  MIGRATION DES CHAMPS TEXTE VERS OUI/NON
#  Table DATABASE - projet Suivi des dossiers DRC
#
#  A EXECUTER AVANT de coller 5_MODIFICATIONS_corrige.bas
###########################################################

CHAMPS CONCERNES (5)

    FAST
    CONSULTATION CPLE Recommandé
    ALERTE DEFAUT
    VALIDATION AINDEP
    URGENCE


###########################################################
#  ETAPE 0 - SAUVEGARDE
###########################################################

Ferme la base, copie le fichier .accdb ailleurs, rouvre.
Les etapes qui suivent suppriment des colonnes : il n'y a pas
d'annulation possible.


###########################################################
#  ETAPE 1 - INVENTAIRE DES VALEURS EXISTANTES
###########################################################

Avant de convertir, regarde ce que les colonnes contiennent
reellement. Ton code n'ecrivait que "Oui" ou "", mais des
saisies manuelles ou d'anciennes versions ont pu laisser autre
chose ("OUI", "oui", "Non", "X"...).

Creer -> Creation de requete -> bouton SQL -> coller -> Executer.
A repeter pour les cinq champs en changeant le nom :

    SELECT [FAST] AS Valeur, Count(*) AS Nb
    FROM [DATABASE]
    GROUP BY [FAST];

Note ce que tu obtiens. Si tu vois uniquement "Oui", des vides
et des Null, l'etape 3 telle qu'elle est ecrite convient.
Si tu vois d'autres valeurs, dis-le moi avant de continuer :
il faudra adapter le test.


###########################################################
#  ETAPE 2 - CREER LES COLONNES CIBLES
###########################################################

Ouvrir la table DATABASE en mode Creation et ajouter cinq
nouveaux champs de type Oui/Non :

    FAST_B
    CPLE_B
    DEFAUT_B
    VALIDIND_B
    URGENCE_B

Pour chacun, dans les proprietes du champ :
    Format          -> Oui/Non
    Valeur par defaut -> 0
    Null interdit   -> Oui

Enregistrer et fermer la table.


###########################################################
#  ETAPE 3 - ALIMENTER LES COLONNES CIBLES
###########################################################

Cinq requetes SQL, a executer une par une.

Le test retenu est = "Oui" et non "chaine non vide" : il est plus
sur. Une valeur "Non" residuelle serait convertie en True par un
test sur la longueur, alors qu'ici elle donne False.

Le Trim et le UCase absorbent les variantes de casse et les
espaces parasites.

    UPDATE [DATABASE]
    SET [FAST_B] = (UCase(Trim(Nz([FAST],""))) = "OUI");

    UPDATE [DATABASE]
    SET [CPLE_B] = (UCase(Trim(Nz([CONSULTATION CPLE Recommandé],""))) = "OUI");

    UPDATE [DATABASE]
    SET [DEFAUT_B] = (UCase(Trim(Nz([ALERTE DEFAUT],""))) = "OUI");

    UPDATE [DATABASE]
    SET [VALIDIND_B] = (UCase(Trim(Nz([VALIDATION AINDEP],""))) = "OUI");

    UPDATE [DATABASE]
    SET [URGENCE_B] = (UCase(Trim(Nz([URGENCE],""))) = "OUI");


###########################################################
#  ETAPE 4 - CONTROLE AVANT BASCULE
###########################################################

Verifie que le nombre de True correspond au nombre de "Oui"
compte a l'etape 1. A repeter pour les cinq :

    SELECT [FAST] AS Ancien, [FAST_B] AS Nouveau, Count(*) AS Nb
    FROM [DATABASE]
    GROUP BY [FAST], [FAST_B];

Tu dois obtenir "Oui" -> True, et tout le reste -> False.
Si les comptes ne tombent pas juste, ARRETE ICI : les anciennes
colonnes sont encore intactes, il suffit de relancer l'etape 3
avec un test corrige.


###########################################################
#  ETAPE 5 - BASCULE
###########################################################

Seulement une fois l'etape 4 validee.

Table DATABASE en mode Creation :

  1. Supprimer la colonne [FAST]
     Renommer [FAST_B] en [FAST]

  2. Supprimer [CONSULTATION CPLE Recommandé]
     Renommer [CPLE_B] en [CONSULTATION CPLE Recommandé]

  3. Supprimer [ALERTE DEFAUT]
     Renommer [DEFAUT_B] en [ALERTE DEFAUT]

  4. Supprimer [VALIDATION AINDEP]
     Renommer [VALIDIND_B] en [VALIDATION AINDEP]

  5. Supprimer [URGENCE]
     Renommer [URGENCE_B] en [URGENCE]

Attention a l'accent de "CONSULTATION CPLE Recommandé" : il doit
etre rigoureusement identique a ce qu'attend le code VBA.


###########################################################
#  ETAPE 6 - CORRECTION DES DONNEES AGF -> AFG
###########################################################

Independant de la migration, mais du meme lot de corrections.
A executer UNE SEULE FOIS, et APRES avoir colle le module
corrige (sinon une nouvelle saisie reintroduit l'erreur) :

    UPDATE [DATABASE]
    SET [TYPE_GARANTIE] = Replace([TYPE_GARANTIE], "AGF", "AFG")
    WHERE [TYPE_GARANTIE] Like "*AGF*";


###########################################################
#  ETAPE 7 - COTE FORMULAIRE
###########################################################

Dans 5_MODIFICATIONS en mode Creation, pour les cinq controles
Option362, Option364, Option371, Option373, Option735 ainsi que
pour ChkCaisse, ChkSignature, ChkMLT, ChkARIZ, ChkAFG, ChkIFC :

    Triple etat -> Non

Cela elimine a la source le cas de la valeur Null, que l'ancien
code traitait sans le savoir de travers.

Verifie aussi que ces controles sont bien NON LIES (propriete
Source controle vide). S'ils etaient lies a un champ, la
migration de type provoquerait une erreur a l'ouverture.


###########################################################
#  ETAPE 8 - CODE
###########################################################

Coller le contenu de 5_MODIFICATIONS_corrige.bas dans le module
de classe du formulaire, puis Debogage -> Compiler.


###########################################################
#  ETAPE 9 - TEST
###########################################################

Sur un dossier de test :
  - cocher URGENCE, fermer le formulaire, rouvrir  -> doit rester coche
  - decocher, rouvrir                              -> doit rester decoche
  - cocher ARIZ + AFG, rouvrir                     -> les deux reviennent
  - verifier dans la table que TYPE_GARANTIE contient "ARIZ, AFG"

Si un UPDATE echoue, tu auras desormais un message d'erreur
explicite avec le SQL fautif, au lieu du silence d'avant.
